# Milestone 5: the XIAO nRF54L15 as a second board

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Capture live IEEE 802.15.4 in Wireshark from a Seeed XIAO nRF54L15, alongside the existing ESP32-C6, through one host and one extcap.

**Architecture:** The board becomes a variable. A `BOARDS` table keyed by USB VID/PID carries each board's radios and capabilities; `INTERFACES` is generated from board x radio rather than hardcoded. New Zephyr firmware speaks the existing `0x5AC6` framing by compiling the *same* `frame.c` the ESP-IDF build does, so byte-identity is structural rather than merely tested.

**Tech Stack:** Python 3.11+ / pytest / pyserial (host), ESP-IDF (existing firmware), nRF Connect SDK + Zephyr (new firmware), Wireshark extcap.

**Spec:** [docs/superpowers/specs/2026-09-14-nrf54l15-second-board-design.md](../specs/2026-09-14-nrf54l15-second-board-design.md)

## Global Constraints

- **Wire format is unchanged.** Magic `0x5AC6`, 10-byte little-endian header, CRC-16/CCITT-FALSE over bytes 0..7. `host/src/esp32c6_sniffer/framing.py` remains the authoritative definition.
- **A lone ESP32-C6 must behave byte-identically to today.** Same three interface names, bare; same `--extcap-config` output, option for option. Wireshark saves capture options against the interface name, so any rename silently drops a user's saved snaplen, channel and filter.
- **A board's radio list records what its firmware implements, not what its silicon can do.** The nRF entry lists `802154` only until BLE firmware exists. An interface that cannot capture is worse than an absent one: it is selectable, and it fails after the operator has committed to a capture.
- **An unrecognised USB VID/PID is skipped, never guessed at.** A board with the wrong capabilities is worse than a board that is absent.
- **USB identities:** ESP32-C6 = `0x303A:0x1001`. XIAO nRF54L15 = `0x2886:0x0066`.
- **Existing test style:** tests live in `host/tests/`, use pytest, and replace hardware by monkeypatching module-level functions. Follow `host/tests/test_multi_board.py`.
- **Commit after every task.** The repo is on `main` with a clean tree; create a branch before Task 1.

```python
#: Every board this plugin knows, keyed by the USB id it enumerates as.
#:
#: Identity has to be settled here rather than over the wire, because the
#: extcap must list its interfaces before any port is opened -- Wireshark asks
#: what exists while nothing is plugged in, and an interface that appears only
#: once a board is attached cannot be configured in advance.
#:
#: `radios` records what the FIRMWARE implements, not what the silicon can do.
#: The nRF54L15 has a BLE radio; it gets a BLE interface when there is firmware
#: behind it and not before.
BOARDS = {
    (0x303A, 0x1001): {
        "id": "esp32c6",
        "display": "ESP32-C6",
        "usb": "303A:1001",
        "radios": ("802154", "wifi", "ble"),
        # An FM8625H RF switch on GPIO3/GPIO14. See firmware/main/board.h.
        "antenna": True,
        "firmware_version": 6,
        "reflash": "idf.py -DSN_MODE=2 build then .\\flash.ps1 -Port <port>",
    },
    (0x2886, 0x0066): {
        "id": "nrf54l15",
        "display": "nRF54L15",
        "usb": "2886:0066",
        # No Wi-Fi radio exists on this part, and BLE waits for firmware.
        "radios": ("802154",),
        # An RF switch, like the C6's: rfsw_pwr on gpio2.3 powers it and
        # rfsw_ctl on gpio2.5 selects between the onboard ceramic antenna and
        # the external IPEX connector. Both are regulator-boot-on in the
        # board's devicetree. Which position selects which antenna is not
        # documented anywhere and is still unknown -- see
        # docs/2026-09-14-nrf54l15-spike.md.
        "antenna": True,
        "firmware_version": 1,
        "reflash": ("west build -b xiao_nrf54l15/nrf54l15/cpuapp then "
                    "west flash --runner openocd"),
    },
}


def list_comports() -> list:
    """Every serial port pyserial can see, or an empty list.

    Its own function so tests can replace the hardware, and so the two ways
    enumeration can fail -- pyserial missing, pyserial raising -- are handled
    in one place. Returning empty rather than raising is deliberate: failing
    to enumerate must never be the reason a capture fails.
    """
    try:
        from serial.tools import list_ports
    except Exception:
        return []
    return list(list_ports.comports())


def find_board_ports() -> list[tuple[str, str]]:
    """(port, board id) for every board we recognise, in enumeration order.

    An unrecognised USB id is skipped rather than guessed at. Guessing
    produces a board whose capabilities are wrong, which is worse than a board
    that is absent: every option in its dialog would be a promise nothing can
    keep.
    """
    try:
        ports = list_comports()
    except Exception:
        return []
    found: list[tuple[str, str]] = []
    for port in ports:
        board = BOARDS.get((port.vid, port.pid))
        if board is not None:
            found.append((port.device, board["id"]))
    return found
```

```python
def board_interfaces() -> list[tuple[str, str]]:
    """Every (interface value, display name) to advertise.

    Two boards mean two radios can capture AT ONCE, which a single shared
    front end otherwise forbids: Zigbee on one and Wi-Fi on the other,
    correlated in one Wireshark session. That is why names carry the port.

    With exactly one board the names stay bare, so nothing that was configured
    before moves -- Wireshark saves capture options against the interface name,
    and renaming an interface silently drops the snaplen, channel and filter a
    user had set. With no board at all we cannot know which one is coming, so
    every board we know is offered bare; an interface that materialises only
    once hardware is attached cannot be configured in advance.
    """
    found = find_board_ports()
    out: list[tuple[str, str]] = []

    if len(found) <= 1:
        present = {board for _port, board in found}
        for name, spec in INTERFACES.items():
            if present and spec["board"] not in present:
                continue
            out.append((name, spec["display"]))
        return out

    for name, spec in INTERFACES.items():
        for port, board in found:
            if board == spec["board"]:
                out.append((f"{name}{PORT_SEPARATOR}{port}",
                            f"{spec['display']} on {port}"))
    return out
```

```c
 * board's SAMD11 CMSIS-DAP bridge over this UART. That bridge, not the radio,
 * is the narrowest part of the system -- see docs/2026-09-14-nrf54l15-spike.md
 * for what it was measured to sustain. */
static const struct device *const uart = DEVICE_DT_GET(DT_CHOSEN(zephyr_console));

static uint16_t seq;
static uint8_t out[SN_HEADER_LEN + SN_MAX_PAYLOAD];
static K_MUTEX_DEFINE(lock);

}

{
    k_mutex_lock(&lock, K_FOREVER);
    const size_t n = sn_frame_encode(out, sizeof(out), type, seq, payload, len);
    if (n == 0) {
        k_mutex_unlock(&lock);
        return -EINVAL;
    }
    seq++;
    for (size_t i = 0; i < n; i++) {
        uart_poll_out(uart, out[i]);
    }
    k_mutex_unlock(&lock);
    return 0;
}
```

```c
#include <stdint.h>

/* Mirrors sn_154_meta_t in firmware/main/radio154.h, which the host unpacks
 * as "<BBbBQ". Packed because the host reads it as a flat little-endian
 * struct with no padding. */
struct __attribute__((packed)) sn_154_meta {
    uint8_t  channel;
    uint8_t  lqi;
    int8_t   rssi_dbm;
    uint8_t  flags;
    uint64_t timestamp_us;
};

int sn_radio154_init(void);
int sn_radio154_set_channel(uint8_t channel);
```

`firmware-nrf54l15/src/radio154.c`:

```c
#include "radio154.h"

#include <zephyr/kernel.h>
#include <zephyr/net/ieee802154_radio.h>

#include "link.h"

static const struct device *const radio =
    DEVICE_DT_GET(DT_CHOSEN(zephyr_ieee802154));
static struct ieee802154_radio_api *api;
static uint8_t current_channel = 11;
static uint32_t dropped;
static uint32_t captured;

int sn_radio154_init(void)
{
    if (!device_is_ready(radio)) {
        return -ENODEV;
    }
    api = (struct ieee802154_radio_api *)radio->api;

    /* Acknowledgements OFF, and this is not optional. The driver
     * auto-acknowledges by default, which would make the sniffer transmit.
     * A sniffer that ACKs is not passive, and this project claims passivity.
     * Nordic's own sample does this for the same reason. */
#if !IS_ENABLED(CONFIG_NRF_802154_SERIALIZATION)
    nrf_802154_auto_ack_set(false);
#endif

    /* Promiscuous, or the driver filters to frames addressed to us and a
     * sniffer sees almost nothing. */
    struct ieee802154_config config = { .promiscuous = true };
    return api->configure(radio, IEEE802154_CONFIG_PROMISCUOUS, &config);
}

int sn_radio154_set_channel(uint8_t channel)
{
    if (channel < 11 || channel > 26) {
        return -EINVAL;
    }
    const int err = api->set_channel(radio, channel);
    if (err == 0) {
        current_channel = channel;
    }
    return err;
}

int sn_radio154_start(void)
{
    return api->start(radio);
}

int sn_radio154_stop(void)
{
    return api->stop(radio);
}

uint32_t sn_radio154_dropped(void)
{
    return dropped;
}

/* Zephyr's raw 802.15.4 mode delivers every received frame here. In RAW mode
 * the application provides this symbol; there is no network stack above it.
 *
 * Signature and accessors are transcribed from the NCS v3.4.0 sample rather
 * than remembered -- it returns int, not enum net_verdict, and the PSDU comes
 * from the buffer chain rather than pkt->frags. */
int net_recv_data(struct net_if *iface, struct net_pkt *pkt)
{
    ARG_UNUSED(iface);

    if (!pkt) {
        return -EINVAL;
    }
    if (net_pkt_is_empty(pkt)) {
        return -ENODATA;
    }

    const uint8_t *psdu = net_buf_frag_last(pkt->buffer)->data;
    size_t length = net_buf_frags_len(pkt->buffer);

    /* The timestamp is a net_ptp_time, seconds plus nanoseconds. There is no
     * net_pkt_timestamp_ns() on this path. */
    struct net_ptp_time *pkt_time = net_pkt_timestamp(pkt);

    struct sn_154_meta meta = {
        .channel = current_channel,
        .lqi = net_pkt_ieee802154_lqi(pkt),
        .rssi_dbm = (int8_t)net_pkt_ieee802154_rssi_dbm(pkt),
        .flags = 0,
        .timestamp_us = pkt_time->second * USEC_PER_SEC +
                        pkt_time->nanosecond / NSEC_PER_USEC,
    };

    static uint8_t payload[sizeof(meta) + 127];
    if (length > 127) {
        length = 127;
    }
    memcpy(payload, &meta, sizeof(meta));
    memcpy(payload + sizeof(meta), psdu, length);

    captured++;
    if (sn_link_send(SN_FRAME_PACKET, payload, sizeof(meta) + length) != 0) {
        dropped++;
    }

    net_pkt_unref(pkt);
    return 0;
}

/* Acknowledgements are not traffic worth reporting, and in promiscuous mode
 * the stack asks what to do with them. */
enum net_verdict ieee802154_handle_ack(struct net_if *iface, struct net_pkt *pkt)
{
    ARG_UNUSED(iface);
    ARG_UNUSED(pkt);
    return NET_DROP;
}
```

The accessor names (`net_pkt_ieee802154_lqi`, `net_pkt_ieee802154_rssi_dbm`, `net_pkt_timestamp_ns`) vary between Zephyr versions. Check them against the SDK pinned in Task 1 and correct them if the build objects; do not guess twice.

- [ ] **Step 3: Write the control handler**

`firmware-nrf54l15/src/control.c`. The payload layouts are defined in the docstring of `host/src/esp32c6_sniffer/control.py`: a command is 5 bytes, `<BI` — command id then a little-endian 32-bit value; a reply is 6 bytes, `<BBI` — the echoed command id, a status, then a value. The command id is echoed rather than correlated by sequence number, because the board assigns sequence numbers and the host cannot know them in advance.

```c
/* The host's side of this is esp32c6_sniffer.control. Commands arrive framed
 * exactly as everything else does, so the same parser handles both.
 *
 * Only four commands are implemented. Every other id gets
 * SN_STATUS_UNKNOWN_COMMAND rather than silence: the host tolerates an
 * unknown reply, but a missing one stalls it until a timeout.
 */

#include <string.h>

#include <zephyr/kernel.h>

#include "commands.h"
#include "frame.h"
#include "link.h"
#include "radio154.h"

#define SN_CMD_PAYLOAD_LEN   5
#define SN_REPLY_PAYLOAD_LEN 6

extern uint32_t sn_firmware_version(void);

static void reply(uint8_t command, uint8_t status, uint32_t value)
{
    uint8_t out[SN_REPLY_PAYLOAD_LEN];
    out[0] = command;
    out[1] = status;
    out[2] = (uint8_t)(value & 0xFFu);
    out[3] = (uint8_t)((value >> 8) & 0xFFu);
    out[4] = (uint8_t)((value >> 16) & 0xFFu);
    out[5] = (uint8_t)((value >> 24) & 0xFFu);
    sn_link_send(SN_FRAME_CONTROL_REPLY, out, sizeof(out));
}

void sn_control_handle(const uint8_t *payload, size_t len)
{
    if (len < SN_CMD_PAYLOAD_LEN) {
        return;
    }
    const uint8_t command = payload[0];
    const uint32_t value = (uint32_t)payload[1] |
                           ((uint32_t)payload[2] << 8) |
                           ((uint32_t)payload[3] << 16) |
                           ((uint32_t)payload[4] << 24);

    switch (command) {
    case SN_CMD_SET_CHANNEL:
        /* Range is checked on the host too, but a board that trusts the wire
         * is one corrupted byte away from tuning somewhere meaningless. */
        reply(command,
              sn_radio154_set_channel((uint8_t)value) == 0 ? SN_STATUS_OK
                                                           : SN_STATUS_BAD_VALUE,
              value);
        break;
    case SN_CMD_START:
        reply(command,
              sn_radio154_start() == 0 ? SN_STATUS_OK : SN_STATUS_FAILED, 0);
        break;
    case SN_CMD_STOP:
        reply(command,
              sn_radio154_stop() == 0 ? SN_STATUS_OK : SN_STATUS_FAILED, 0);
        break;
    case SN_CMD_GET_INFO:
        /* The host refuses to open a capture until this matches
         * EXPECTED_FIRMWARE_VERSIONS["nrf54l15"], because an older board packs
         * its metadata differently and every field would then decode to a
         * confident wrong number rather than an error. */
        reply(command, SN_STATUS_OK, sn_firmware_version());
        break;
    default:
        reply(command, SN_STATUS_UNKNOWN_COMMAND, 0);
        break;
    }
}
```

Feed it from the UART: add an interrupt-driven receive callback that accumulates bytes, decodes frames with the same header rules `frame.h` defines, and calls `sn_control_handle()` for each `SN_FRAME_CONTROL_CMD`. Expose `sn_firmware_version()` from `main.c` returning `SN_FIRMWARE_VERSION`, so `control.c` need not see the build-mode macros.

The host accepts four lengths and pads the rest with zeros — `<8I>`, `<16I>`, `<18I>`, `<20I>`. The shortest, `<8I>`, is five link counters followed by three 802.15.4 counters, and it is exactly what this board has to say. The longer forms carry Wi-Fi counters that will never be anything but zero here, and sending zeros would be claiming a measurement rather than omitting one.

Order, which must match exactly:

| # | Field | Block |
|---|---|---|
| 1 | `frames_sent` | link |
| 2 | `frames_dropped_ringfull` | link |
| 3 | `short_writes` | link |
| 4 | `tx_stalls` | link |
| 5 | `bytes_sent` | link |
| 6 | `frames_captured` | 802.15.4 |
| 7 | `isr_queue_full` | 802.15.4 |
| 8 | `link_rejected` | 802.15.4 |

A field out of order here decodes into plausible wrong numbers, which is worse than no counters at all — the whole point of publishing them is that "did I miss anything" becomes answerable.

```c
 * firmware. The host reads it as "<8I" and zero-fills the Wi-Fi counters it

    uint32_t frames_sent;
    uint32_t frames_dropped_ringfull;
    uint32_t short_writes;
    uint32_t tx_stalls;
    uint32_t bytes_sent;
    uint32_t frames_captured;
    uint32_t isr_queue_full;
    uint32_t link_rejected;
};

static void stats_tick(struct k_work *work)
{

        .frames_sent = sn_link_frames_sent(),
        .frames_dropped_ringfull = 0,
        .short_writes = 0,
        .tx_stalls = 0,
        .bytes_sent = sn_link_bytes_sent(),

        .isr_queue_full = 0,
        .link_rejected = sn_radio154_dropped(),

}

static K_WORK_DELAYABLE_DEFINE(stats_work, stats_tick);
```
